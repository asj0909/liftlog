# 要件定義書 — 筋トレ記録アプリ LiftLog

| 項目 | 内容 |
|---|---|
| 文書バージョン | 0.2（ドラフト） |
| 作成日 | 2026-10-28 |
| 対象フェーズ | MVP（第1リリース） |

---

## 1. 概要・目的

ジムでのウェイトトレーニングを、スマートフォンから素早く記録し、Web の広い画面で成長の推移を確認できるアプリを開発する。

- **モバイル（Android / iOS）**：トレーニング中にセット（重量・回数）を最小の操作で記録する
- **Web**：記録の一覧・推移グラフを大きな画面で振り返る

Flutter による単一コードベースで 3 プラットフォームに対応し、バックエンドには Supabase を採用する。

## 2. 対象ユーザー

- 週 2〜5 回程度ジムに通い、フリーウェイト・マシンでトレーニングする個人
- 紙のメモやスマホのメモアプリで記録しており、推移を把握しづらいと感じている人
- 初期リリースでは開発者本人を主要ユーザーとして想定し、実利用でのフィードバックを優先する

## 3. 対象プラットフォーム

| プラットフォーム | 対応範囲 |
|---|---|
| Android | Android 8.0（API 26）以上 |
| iOS | iOS 15 以上 |
| Web | 最新版の Chrome / Safari / Edge（デスクトップ・モバイルブラウザ） |

## 4. システム構成（概要）

- クライアント：Flutter（Dart）
- 認証：Supabase Auth
- データベース：Supabase（PostgreSQL）、行レベルセキュリティ（RLS）でユーザーごとにデータを分離
- 集計：グラフ用の集計は DB 側（ビューまたは関数）で行い、クライアントの負荷を抑える

※ 詳細は基本設計書で定義する。

## 5. 機能要件（MVP）

### F-01 認証
- メールアドレス＋パスワードでサインアップ・ログイン・ログアウトできる
- パスワードリセット（メール送信）ができる
- ログイン状態はアプリ再起動後も保持される

### F-02 種目管理
- プリセット種目（「14. プリセット種目一覧」参照）を利用できる
- ユーザー独自の種目を追加・編集・削除できる
- 種目は部位カテゴリ（胸・背中・脚・肩・腕・体幹・その他）で分類される
- 記録が存在する種目を削除する場合は確認ダイアログを表示する

### F-03 ワークアウト記録
- 日付ごとにワークアウト（セッション）を作成できる（デフォルトは当日）
- セッションに種目を追加し、各種目にセットを記録できる
  - セット項目：重量（kg）、回数、メモ（任意）
  - 重量は 0 以上とする。自重種目（懸垂・ディップス等）は 0kg、加重時は追加重量のみを入力する
- セットの追加・編集・削除・並び替えができる
- 直前のセットの重量・回数を初期値として入力でき、少ない操作で連続記録できる

### F-04 前回記録の表示
- 種目のセット入力画面で、同じ種目の前回セッションの記録を参照表示する

### F-05 履歴閲覧
- 過去のワークアウトを日付の新しい順に一覧表示する
- カレンダー表示でトレーニング実施日を確認できる
- セッションを選択すると詳細（種目・セット）を表示し、編集できる

### F-06 推移グラフ
- 種目を選択し、以下の指標の推移を折れ線グラフで表示する
  - 最大重量（その日の最も重いセット）
  - 推定 1RM（Epley 式：重量 × (1 + 回数 / 30)）
  - 総ボリューム（重量 × 回数 の合計）
- 期間フィルタ：1 か月 / 3 か月 / 6 か月 / 1 年 / 全期間
- Web（広い画面）では複数のグラフを並べて表示できる

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | セット記録の保存は通常の通信環境で 1 秒以内に完了表示する。グラフは 1 年分のデータで 2 秒以内に表示する |
| 操作性 | セット 1 件の記録を 3 タップ以内で完了できる（直前値の流用時） |
| セキュリティ | 全テーブルに RLS を設定し、本人以外のデータは参照・更新できない。通信は HTTPS のみ |
| レスポンシブ | 幅 600px 未満をモバイル、600px 以上をタブレット／デスクトップとしてレイアウトを切り替える |
| 多言語 | UI 言語は日本語。将来の多言語化に備え、文言はリソース化する |
| 単位 | 重量の単位は kg（lb 対応はスコープ外） |
| 品質 | ドメインロジック・状態管理は単体テスト、主要画面はウィジェットテストを作成する。主要フローの結合テストを 1 本以上用意する |
| 保守性 | 機能単位のディレクトリ構成とし、UI・状態管理・データアクセスを分離する |

## 8. データ項目（概要）

| エンティティ | 主な項目 |
|---|---|
| ユーザー | ID、メールアドレス（Supabase Auth 管理） |
| 種目 | ID、名称、部位カテゴリ、プリセットフラグ、所有ユーザー ID |
| ワークアウト | ID、ユーザー ID、実施日、メモ |
| ワークアウト種目 | ID、ワークアウト ID、種目 ID、表示順 |
| セット | ID、ワークアウト種目 ID、表示順、重量（kg）、回数、メモ |

## 9. スコープ外（MVP 対象外）

以下は第 2 リリース以降で検討する。

- オフライン記録と自動同期
- ルーティン（メニュー）テンプレート
- 週間・月間レポート
- 体重を考慮した自重種目の負荷計算、有酸素運動・時間計測型の記録
- インターバルタイマー
- Google / Apple アカウントによるログイン
- Apple Health / Health Connect 連携
- lb 単位対応、SNS 共有

## 10. 前提・制約

- 開発は個人で行い、生成 AI（Claude）を設計・実装・テストに活用する
- Supabase は無料プランの範囲で運用する
- ストア公開は MVP の必須要件としない（Web はデプロイして動作確認可能な状態を目標とする）

## 11. 受け入れ基準（抜粋）

- サインアップ後、ログアウト・再ログインしても自分の記録が表示される
- 別アカウントでログインした場合、他ユーザーの記録が一切表示されない
- 記録したセットが、履歴一覧・セッション詳細・推移グラフのすべてに反映される
- Android・iOS・Web の 3 環境で、記録から推移グラフ表示までの一連の操作が完了できる

## 12. 用語集

| 用語 | 意味 |
|---|---|
| ワークアウト（セッション） | 1 回のトレーニング（1 日分の記録単位） |
| セット | 1 種目で一定回数を連続して行う 1 まとまり |
| 推定 1RM | 1 回だけ挙げられる最大重量の推定値 |
| ボリューム | 重量 × 回数 の合計。トレーニング量の指標 |
| RLS | Row Level Security。DB の行単位でアクセスを制御する仕組み |
